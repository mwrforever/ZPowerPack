## 一、意图与背景

V1 看板上线后被用户全量否定：样式「太丑」、实时统计口径「绝对有问题」、且真机打开看板整端卡顿。2026-11-22 晚协商，用户逐项拍板：

1. **视觉基准换成 Dribbble「AI Usage Widget」**（`docs/refs/dribbble-27698368-ai-usage-widget.png`，版权作品仅内部参考、不得随插件分发）：厂商行（环形进度 + 状态句 + 双窗口百分比）+ 24h 趋势折线 + 底部结论文案。只取布局骨架，不取紫渐变展示背景。
2. **八张报表全砍**（吞吐对比/TTFT 分布/上下文→速率/时段热力/按项目/工具统计/厂商稳定性/直方图）。
3. **token 实时速率保留**，但计算方式重做——旧口径（60s 窗口时长加权 + EMA + 三态保持）判死。
4. **额度官方接口每 60 秒自动拉取**（用户最终拍板，替代旧 5min TTL；此前一度议 10s，因限流风险收敛到 60s）+ 看板内**手动同步按钮**。
5. **常驻素条 + 唯一入口**（2026-11-22 追加拍板）：输入控制台与模型选择同行放常驻素条（composer.status 插槽，宿主渲染、无样式自由度），位置在模型选择器**左侧**（宿主默认 DOM 顺序即插件条在前，零成本满足）；砍掉 nav/侧栏入口，素条为唯一入口；点击打开主内容区看板面板（宿主无锚定弹窗，富样式全在面板内自绘）。

## 二、决定性新事实：官方流式速率事件存在（推翻 V1 定论）

V1 设计断言「流式速率数据源不存在，model_usage 行完成才落库」（E1）。本会话逆向扩展宿主源码发现该断言只对了一半——**db 确实无流式信号，但扩展 API 面有官方推送事件**：

- 宿主声明表含全量 API：`models.list` / `models.onDidGenerate`（subscribe）、`sessions.onDidChangeConversation` 等（`context/env/grants/notifications/settings/workbench` 亦有）。
- **`models.onDidGenerate` 事件载荷**（宿主源码 Zz 声明直录）：

```json
{
  "sessionId": "...", "requestId": "...",
  "model": { "providerId": "...", "modelId": "..." },
  "phase": "streaming | final",
  "outputTokensPerSecond": 428.6,
  "outputTokens": 12345,          // 可选
  "timeToFirstTokenMs": 890       // 可选
}
```

- `grant: "none"`（无需授权），backend `"pump"`（推送通道）。**应用自己就算好了实时 tok/s 并主动推**——这正是用户问「zcode 不提供这个流的一些输出信息吗」的答案：提供，且是算好直给的。
- 宿主侧订阅机制实证存在：`subscribe(pluginId, capabilityId, input, listenerKey, listener)`，对声明表校验（not-declared 则拒）。**扩展侧 ctx 的挂载形态**（`ctx.models.onDidGenerate(...)` 还是通用订阅入口）与**推送节奏**（流式期每秒几次）需 Task 0 探针实测钉死。

## 三、目标 / 非目标 / 反目标

### 目标
- G1 **看板视图按 AI Usage Widget 卡片骨架重写**：厂商实例行 ×（环形进度 + 5h 状态句 + 周/月 副行 + 右侧双窗口百分比）+ 24h 用量趋势折线 + 底部推算结论 + 手动同步按钮 + 实时速率条。
- G2 **实时速率 = 订阅 `models.onDidGenerate`**：生成中数字实时动（官方 `outputTokensPerSecond`），无轮询、无扫库、无平滑补丁。兜底链见 §五.5。
- G3 **额度 60s 自动 + 手动即时**：官方接口按窗口组合（沿用拍板：智谱 5h+周、Kimi 5h+月、OpenCode 5h+周+月；Qwen 不入额度）。
- G4 **全链路 O(新行)**：db 只做 60s 增量拉取 + 小时桶落桶，任何时刻不重扫全量缓冲。
- G5 **常驻素条四态**（composer.status，唯一入口）：生成中显速率、并行显合计、空闲显额度水位、无数据显待机；悬停 tooltip 给全量；点击打开看板面板。不注册 nav.primary/sidePane.launcher。
- G6 **取数全推送**：视图经资源订阅 + 扩展侧 notify 推送更新，1s 轮询退役。

### 非目标（V2 不做）
- 不做 Effort 三档推演控件（设计稿元素，Claude 专有概念，我们无对应物）。
- 不复刻紫渐变展示背景/毛玻璃装饰（用户反感主题化装饰；跟随 app 面板底色）。
- 不做已砍八报表的任何回归入口。
- 不做额度阈值告警、成本估算。

### 反目标（出现即失败）
- **任何「看起来在动但数据没动」的数字**（旧 EMA/held 的教训：飞行期假装有值是编造）。
- 逐秒扫全量缓冲 / 逐秒打官方接口（真机卡顿根因，绝不允许复发）。
- 密钥进入快照/日志/视图（apiKey 只活在请求头）。

## 四、方案取舍记录

| 决策点 | 备选 | 定案 | 理由 |
|---|---|---|---|
| 报表去留 | A 全砍 / B 折叠留几张 / C 次级页全保 | **A** | 设计稿无这些元素；计算量随报表层整体消失 |
| 速率来源 | α db 派生（60s 窗口或最新请求直给）/ β `onDidGenerate` 订阅 / γ 60s 挂钟吞吐 | **β** | α 被「完成才落库」框死（飞行期库中无信号，旧口径的病根）；γ 飞行期数值衰减误导；β 是官方算好的真值推送 |
| 额度节奏 | 10s / 60s | **60s + 手动按钮** | 用户拍板；三实例七窗口 10s ≈ 42 次/分钟有限流风险（OpenCode 接口自带 rate-limited 状态位） |

| 视图取数 | 1s 轮询 / resources/subscribe 订阅推送 | **Task 0 实测定** | 宿主有 `resources/subscribe`+`resources/updated`，但沙箱 `window.zcode` 桥是否暴露未实测；订阅不可用则回退 1s 轻轮询（载荷已大幅变小） |

## 五、设计定案

### 1. 布局（卡片四区，深色，大圆角）

```
┌───────────────────────────────────────────┐
│ ● 428 tok/s · glm-4.7        〔手动同步〕↻ │  ← 速率条：生成中=事件直给
│                                           │     （右上角按钮，见 §五.4）
├───────────────────────────────────────────┤
│ ◕  智谱 GLM-4.7         5h 剩27% · 周 剩59%│  ← 环=5h 剩余%（语义色）
│    5h · 2h12m 后重置                        │     状态句=官方重置时刻
│    周 · 剩 2d 4h                            │
├───────────────────────────────────────────┤
│ ◕  Kimi K2               5h 剩88% · 月 剩73%│  ← 每实例一行（全实例展示，不设行数上限）
│    5h · 4h48m 后重置                        │
├───────────────────────────────────────────┤
│  近 24 小时                                 │
│   ⋰⋰⋰⋰⋰⋰⋰（橙色面积折线）                  │  ← 小时桶 24+当前
├───────────────────────────────────────────┤
│  按近半小时速度，智谱 5h 撑不到重置（推算）  │  ← 线性外推，诚实标注
└───────────────────────────────────────────┘
```

- **显示语义：统一为剩余额度（2026-11-23 用户拍板）**——一切百分比/环/文案一律表达「还剩多少」，不显示已用。官方接口给的是已用 percent，**在 view-model 边界统一换算 `剩余 = 100 − 已用`**（单一换算点；快照内保持官方原始语义）。环填充 = 剩余比例（满环=额度充足）。
- **环形进度**：SVG `stroke-dasharray` 内联实现（单文件自包含约束）。语义色阈值（按剩余）：≤15% 珊瑚（紧张）、≤40% 琥珀、否则青/绿系健康色；与设计稿「橙=紧张、绿=充足」语系对齐（阈值与旧「已用 ≥85/≥60」机械对偶）。
- **厂商行状态句**：官方 `resetsAt` 有值 → 相对时长（≤48h）或绝对时刻；无值 → 诚实兜底（「滚动窗口」/「订阅日重置」），不编造。
- **副行（周/月）**：`周 · 剩 2d 4h`（官方 percent+resetsAt 换算）；无官方数据 → 省略百分比（不编造）。OpenCode 三窗口：右侧枚举三枚剩余百分比（`5h 剩73% · 周 剩41% · 月 剩12%`），副行并列剩余时长（已拍板 a 方案）。
- **厂商行顺序**：5h 剩余百分比升序（最紧张的排最上）。

### 2. 速率条（事件驱动，唯一实时元素）

- 订阅 `models.onDidGenerate` → 维护活跃流状态（含 model、phase、tok/s、outputTokens、接收时刻）。**多流并发口径（已拍板 a 方案）**：面板速率条各活跃流并列显示（`● glm-4.7 428 · kimi-k2 372 tok/s`），无并发退化单流；素条与 tooltip 取合计。
- **会话作用域（2026-11-23 修订，用户拍板 #1）**：速率只算**当前会话**（素条所在 composer 的会话），不做全局跨会话聚合。实现依据（宿主源码实证）：`slots.update(id, patch, scope)` 第三参支持会话作用域；`workbench.onDidChange`（subscribe，grant:none）可感知活跃会话集合。事件按 sessionId 归组，素条按会话分别推送；面板取打开视图时 scope 携带的会话，**无会话 scope 时取全局多流并列（终审裁定：app scope 下全局是诚实形态，「最近活跃会话」会张冠李戴）**；`recent`/`fallback` 末值不做会话归属（终审裁定：改 live-rate 契约不值，app scope 影响小）。
- streaming：`● 428 tok/s · glm-4.7`，圆点呼吸动效（CSS 动画，prefers-reduced-motion 关闭）。~~副行「近 60 秒产出 X token」~~ **删除（终审裁定：分钟粒度桶给不出诚实的 60 秒产出值，不编造）**。
- final：显示末次值 + `完成于 Xs 前`；**final 事件不受 1s 节流约束（终审修复：否则「生成中」最长滞留 60s，正落反目标）**。
- 超 5 分钟无事件：`空闲 · 上次活动 HH:MM`。
- **无 EMA、无窗口加权、无三态保持**——展示值=官方推送值原样，数据时刻=事件接收时刻。

### 3. 数据源与节奏（全量表）

| 数据 | 来源 | 节奏 | 计算量 |
|---|---|---|---|
| 实时速率 | `models.onDidGenerate` 订阅推送 | 事件驱动 | O(事件) |
| 额度百分比/重置时刻 | 官方接口（三厂商） | 60s 自动 + 手动触发 | 每实例每窗口 1 请求 |
| 24h 趋势 | db `model_usage` rowid 增量 → 小时桶（激活首拍有界回填近 24h） | 60s 一拍 | O(新行) |
| 额度兜底分子（仅 5h 窗口；周/月不做，见下） | per-instance 小时桶求和 | 同上 | O(实例×25桶) |
| 底部结论 | 官方 percent 采样序列外推 | 每次 60s 拉取后重算 | O(采样数) |

- **小时桶**：按实例维度 `Map<providerId, Map<epochHour, {in, out, reqs}>>`，新行按 `completed_at` 落桶 O(1)，每实例只留 25 桶（24h+当前）；24h 趋势=跨实例按小时求和（廉价）。替代旧 24h 环形缓冲全量行持有。
- **初始回填**（builder check 裁量回填）：激活首拍**不做全量拉取**（V1 游标从 0 起步全量拉 8 万行是卡顿链一环，禁止重演）。一次性有界查询 `WHERE completed_at ≥ now−24h`（只 SELECT 所需列）→ 直接落桶 → 行用后即弃；rowid 游标从回填行的最大 rowid 起步。空闲态「上次活动 HH:MM」的种子时刻取回填数据里最近完成行。游标与桶**不做跨重启持久化**（重启代价=一次有界回填，非必要复杂度不引入）。
- **额度兜底收窄**（builder check 裁量回填）：本地分子兜底**仅限 5h 窗口**（per-instance 桶求和，桶界=官方 resetsAt 或 [now−5h,now]）。周/月窗口官方失败时**不做本地分子**——24h 底座对 7d/30d 天然算不准（V1 的全缓冲周分子本就依赖"进程连活 7 天"的脆弱假设，属隐性失真），官方失败只显示状态句「官方接口不可用」。此改动同步收窄 `quota.mjs` `usageInWindow` 的兜底职责。
- **结论句算法**（我的裁量，实施可微调）：保留最近 ~30 分钟官方 percent 采样（60s 一个，≤30 个点）；对 5h 水位最高的实例，用首尾差线性外推到重置时刻 → 「撑得到/撑不到重置」；采样 <5 个或增量 ≈0 → 「消耗速度尚不足以推算」。不依赖官方 limit（OpenCode 无绝对分母，percent 差值法对其同样成立）。
- **后台/前台同节奏**：60s。速率靠事件、趋势是小时粒度、额度 60s——看板开关不影响拍频；手动按钮补即时性。防重入护栏保留（一轮没跑完跳过下一拍）。

### 4. 手动同步按钮

- 视图按钮 → `window.zcode.readResource("zpowerpack://sync")` → 宿主 read 回调内立即拉全部实例官方额度 → 返回最新额度 JSON → 视图即时重渲。
- 按钮态：拉取中禁用+旋转图标（超时 10s 复位）；失败 toast 文案「同步失败：官方接口不可达」。
- 借 read 通道做触发属宿主既有机制内正规用法（V1 实证 read 回调在扩展进程执行），不改宿主、不需新授权。

### 5. 兜底链（订阅不可达时）

Task 0 探针若证实 `models.onDidGenerate` 无法从扩展 ctx 订阅（挂载形态缺失/被 feature gate），降级为「最新完成请求直给」：速率条显示最近落库行的 `产出÷生成段`，附数据时刻；同步回报用户改设计。**降级不阻塞其余部分**（额度/趋势/结论均不依赖该订阅）。

### 6. 常驻素条（composer.status，唯一入口；宿主渲染、无样式自由度——zod 校验 + 渲染组件双向实证）

**插槽契约（钉死）**：可写面仅 `{text≤40, tooltip≤200, visible, badge}`，无任何颜色/变体/样式字段；**badge 在 composer 渲染组件中不消费（渲染侧丢弃，仅 nav.primary 渲染 badge）——V2 不再推送 badge**（V1 推 badge 从未显示，属往不存在的洞里灌数据）；图标限 23 个命名词表，取 `gauge`；文本可视宽约 160px 超长截断；紧凑模式仅显示图标；素条渲染在模型选择器**左侧**（宿主默认 DOM 顺序：插件条在前，已拍板维持）。

四态文本（与宿主 ghost 按钮同款素样式：28px 高、圆角、弱化灰小字、tabular-nums 等宽数字）：

| 态 | 素条文本 | tooltip（≤200 字符） |
|---|---|---|
| ① 生成中（仅主代理） | `[gauge] 428 tok/s · 5h 剩27%` | `智谱 5h 剩余 27%（2h12m 后重置）· 周 剩余 59% · 主 428 tok/s · 点击查看详情` |
| ② 生成中（主+子并行） | `[gauge] 428+96 tok/s · 5h 剩27%` | `智谱 5h 剩余 27% · 周 剩余 59% · 主 428 · 子 96 tok/s（2 路并行）· 点击查看详情` |
| ③ 空闲 | `[gauge] 智谱 5h 剩27% · 周 剩59%`（跟随最近请求厂商） | 同①去掉速率段 |
| ④ 无数据（刚装/未配 provider） | `[gauge] ZPowerPack 待机` | `ZPowerPack 用量速览 · 点击打开看板` |

- 点击 → 运行命令 → `views.open` 打开看板面板（**唯一入口**；不注册 nav.primary / sidePane.launcher）。
- 同值去重防刷屏保留（速率取整后同值不推）。
- **会话作用域推送（2026-11-23 修订 #1）**：素条四态按会话分别推送（`slots.update` 第三参作用域，宿主源码实证）；速率只算当前会话。
- **tooltip 额度作用域（2026-11-23 二次修订，用户质疑后复核成立）**：额度=**聚焦会话当前模型选择的供应商**——`context.get({sessionId})` 返回结构带 `model:{providerId, modelId, contextWindow}`（活声明表实证，grant:none），`workbench.onDidChange` 提供聚焦会话集合。仅新会话未发首条消息（组合上下文为 null）时回退该会话最近请求供应商。撤销同日早先「选中状态无 API」的近似结论（系首查只看接口名、未翻返回结构所致）。

### 1. 子代理速率的宿主硬约束（决定口径）

宿主 `models.onDidGenerate` 的推送泵只跟踪 `querySource === "main_turn"` 的请求（3.19.1 源码实证：`out/host/index.js` 中 `Rde="main_turn"` 及 `m.querySource===Rde` 判据；`stream.chunk` 带 `parentToolCallId` 的块直接丢弃）。子代理请求的 `querySource="subagent"`，在宿主侧被过滤，扩展永远收不到子代理流事件。用户拍板：**只显示主代理速率**，不用 db 落库行做非实时近似（那会重新引入 db 读取且违背「实时」）。

### 2. 展示口径

- 生成中：当前会话活跃主流速率（官方 `outputTokensPerSecond` 原值；同会话多流取均值，宿主同刻通常仅一路主流）。
- final（主代理停工）：收流并记末值，素条持续展示「之前的速率」——不清零、不切换空闲文案。
- 为空不展示：会话自插件激活以来从未收到生成事件 → 推送 `visible:false`（不展示占位文案）。
- 速率文案 = `fmt1` 一位小数去尾零 + ` tok/s`（如 `428 tok/s`、`120.8 tok/s`），远在 text≤40 硬约束内。

### 3. 作用域与推送

- `slots.update("zpowerpack-mini", {text, visible}, {sessionId})`：每个可见会话各自一条，多窗口不串值。
- 目标会话 = `workbench.onDidChange` 的 `sessions[]`；激活时 `visibleSessions()` 补初值；订阅不可达 / 列表为空时只跟随最近事件会话；无任何目标时不推全局值。
- 事件节流 1s（streaming 中间帧丢弃；宿主推送间隔 ≥500ms），**final 绕过**；同会话同值去重，宿主拒收不写去重键（下一事件重试）。
- `composer.status` 条目必须挂命令目标（宿主 schema 硬约束）：保留空操作命令 `zpowerpack-rate-status`，不注册任何视图/资源。

### 6. 2026-11-24 速率口径实测校准（v0.3.1 / v0.3.2）

对官方 `outputTokensPerSecond` 做了源码 + 真机数据交叉验证，结论与修正如下：

| 项 | 宿主口径（源码实证） | 验证结果 |
|---|---|---|
| 生成中（streaming） | `累计 chunk 字符数 ÷ 3 ÷ 自首块起毫秒 × 1000`（`mu=3`；`chunkLength` 为字符数，含 thought+text 通道） | **字符估算**，不是真实 token；本机 10 条真实请求与 `output_tokens` 对比偏差 **−26%~+26%**（内容相关，中文更低）；且为累计平均 |
| 停工（final） | `真实 usage outputTokens × 1000 ÷ (durationMs − timeToFirstContentMs)` | **真实 token 速率**；探针请求 final=120.77 tok/s，db 遥测独立复算 116.55 tok/s（差 3.5%，TTFT/时间戳来源差异） |
| 首帧伪影 | 每个请求首条 streaming 事件的窗口仅几毫秒（恒立即推送，宿主 500ms 节流对首帧不生效） | 探针实测 4666.67 tok/s（首帧）→ 90.12（+615ms）→ 120.77（final）；首帧是计算伪影 |

用户拍板修正（v0.3.1）：
1. **首帧过滤**：每个 requestId 的第一条 streaming 事件只建状态、不上屏，从第二条开始显示（约 +500ms），消除开头几千 tok/s 的闪值；首帧不占推送节流窗口。
2. **估算标注**：生成中文本改为 `~428 tok/s`（字符估算）；final 文本保持 `120.8 tok/s`（真实 token 精值），一眼区分。
3. final 值不改：它本来就是官方真实 token 口径；插件仍原样透传，不做二次换算。
4. **滞留流看门狗**：取消/失败请求可能收不到 final（宿主泵只在完成指标到达时发 final），活跃流静默 60s 后清除并刷新素条，不长期显示 `~` 假装仍在生成；final 精值不受清理影响。看门狗为一次性定时器（unref），stop 时清理。

**v0.3.2 二次反馈（0.3.1 上机后仍偶发 10000+ tok/s）**：根因是 reasoning/tool 分块经常成块到达（实测单块近 1 万字符），宿主累计字符数在 500ms 窗口内被瞬间拉高，第二帧起仍会算出万级估算值；首帧过滤只挡第一帧，挡不住中途大块。v0.3.2 曾用 `MAX_LIVE_TPS=2000` 固定上限拦截，**被用户否决**（不能用砍上限的方式掩盖问题）。

**v0.3.3 终局口径（用户拍板）**：新请求开场**先展示该会话上一次 final 的精确速率**（真实 token 值，不带 `~`），累计收到 `LIVE_WARMUP_EVENTS = 4` 条 streaming（宿主 ≥500ms/条，约 2s）后才切到实时估算值（`~` 标注）；期间的大块分块尖峰全部不上屏。重试/停滞（同一 requestId 静默 >3s，宿主会重置 chars/firstChunkAt）重新进入 warm-up，继续展示上一次精值。无历史值时开场保持隐藏，不编造占位。final 始终是真实 token 精值并保留为「之前的速率」；60s 滞留看门狗保留。
